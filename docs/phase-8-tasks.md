# P8：接入复用与 Rust 发布候选

## 目标与状态

状态：全部待开发（2026-09-06）。见 [整体规划](development-plan.md)。验证 Axiom
能被独立宿主采用，并形成有明确兼容范围、可复现示例和维护证据的 Rust 交付。
本阶段不预定 1.0，不要求全部 Adapter 或第二语言实现；真正发布/上传包另按当时授权执行。
各项按 README 验证，性能测量不替代行为测试，不新增无依据的质量阈值。

## P8-001：第二宿主接入对照

- **依赖**：P3-R03；使用状态能力的部分依赖对应 P4/P5 任务。
- **交付**：一个不同于首个真实宿主、也不同于 lab-inspect 的接入记录；业务能力、线程/所有权差异、代码位置和一次参数变更的维护证据。
- **范围**：选一个代表性工作流即可，不要求复制整个应用。区分业务代码、契约声明、Value 转换和入口接线，记录实际问题而非只统计代码行数。
- **验收**：按公开 API 接入，不读取 core 私有存储；同一实现可供两个入口使用；新增/修改参数时遗漏转换可被测试发现。没有第二宿主时标记待选，不以第二份计算器完成验收。

## P8-002：基于接入证据的最小易用性改进

- **依赖**：P8-001。
- **交付**：维护成本比较与决定；确有共同重复时交付最小 typed helper/转换辅助及迁移示例，否则记录保留现状的理由。
- **范围**：不自动引入宏、代码生成、泛型注册框架或默认值注入；helper 必须保留严格类型和结构化错误，由契约拥有验证规则。
- **验收**：同一参数变更在改进前后行为一致、维护位置减少或错误更容易定位；错误输入不静默修复；没有共同需求时文档决策即可完成本项，不制造无调用方公共 API。

## P8-003：嵌入生命周期与可控退出

- **依赖**：P4-006、P5-007、P6-006、P8-001。
- **交付**：实际宿主启动/注册/服务/停止顺序、已发现的所有权缺陷修复及回归。
- **范围**：检查 RuntimeHandle 失效、能力循环引用、未完成工作、资源析构线程、活动订阅和 Adapter 退出；依所属模块已有契约修复，不新增另一个全局生命周期管理器。
- **验收**：正常退出、外部连接中断和工作失败后可释放该释放的状态；析构不跨线程误用、不无限等待；借用/非拥有对象的宿主责任有明确示例。

## P8-004：公开接入文档与兼容清单

- **依赖**：P8-002、P8-003；第二 Adapter 说明依赖 P7 对应已完成增量。
- **交付**：从已有强类型业务到注册/调用/状态/诊断的教程、公开 API rustdoc、协议版本与 API 迁移说明。
- **范围**：澄清 metadata-only CapabilityRegistry 与可执行 Runtime；给出不支持的行为、平台/工具链实际范围、错误和引用示例；消除 src/lib.rs 中仅适用于 P3 的阶段限制说明。
- **验收**：新宿主使用者按教程完成一个能力接入；示例实际运行，路径/进程操作可移植；文档中的每项支持声明指向代码或测试，历史限制与当前限制不混淆。

## P8-005：代表性性能与容量基线

- **依赖**：P8-001、P8-003。
- **交付**：原生业务、Runtime、Command、Adapter 的分层测量脚本及报告，记录环境、输入规模和复现命令。
- **范围**：测量契约校验/复制、能力列表、资源/任务数量、通知缓冲及端到端延迟；由宿主用量定义负载与可接受预算。只修复已影响场景的瓶颈，不因 clone 存在就重构。
- **验收**：结果可重现到合理波动范围；容量满/过大输出等行为明确，不静默截断；如需优化，修改后语义不变且有前后数据。无实测证据不声称“零开销”或通用规模承诺。

## P8-006：发布候选与采用验收

- **依赖**：P8-004、P8-005、P7 已声明交付范围。
- **交付**：发布候选说明、版本/兼容策略、变更日志、包内容检查、真实宿主反馈与开放问题清单；记录选定候选 commit。
- **范围**：区分 Rust API、Command 版本、Adapter 协议版本；说明 breaking change 的迁移与已实现能力集。完整 M4 候选覆盖 M1～M3；提前发布同步预览版须明确其子集，不标为完整 M4。
- **验收**：最终候选通过 README 所需验证；核心依赖方向未退化；干净环境可按说明构建/运行；两个真实宿主的结果可追溯。没有阻塞缺陷才报告可发布，不把计划中的 P9 能力写成已支持。
