# P7：第二 Adapter 与实际 Agent 使用

## 目标与状态

状态：全部待开发（2026-09-06）。依据 [整体规划](development-plan.md) 与
[设计第 8、18、19 节](Axiom-design.md)。默认评估 MCP 作为 Agent 入口；协议与版本
在 P7-001 确认，本文不宣称符合任何尚未验证的 MCP 版本。
本阶段只实现一个有实际消费方的第二 Adapter。Python/CLI/RPC 是替代或后续候选，
不打包为本阶段必做。同步路径可在 P6 前交付；完整状态验收按依赖后置。

## P7-001：客户端场景和协议映射决策

- **依赖**：P3-R01 的能力/调用方清单和现有 Command；不要求 P4～P6 完成。
- **交付**：`docs/adapter-mapping.md`，记录实际客户端、官方协议/SDK 版本、所需操作和支持矩阵。
- **范围**：实施时核验官方规范；列明工具描述、结果/错误、资源引用、Task、通知的映射。协议中的同名概念不自动等价于 Axiom Resource/Task；缺少标准映射时选择显式工具或报告不支持。
- **验收**：一个能启动的客户端连接方案、发现/调用请求样例和预期结果；按现有线程亲和模型说明请求如何送到所属线程。若选择非 MCP，记录原因和 Agent 如何访问，不额外建设另一 Adapter。

## P7-002：契约和动态值的外部映射

- **依赖**：P7-001。
- **交付**：独立 Adapter crate 的发现导出、值编码和映射测试；直接读取核心权威契约。
- **范围**：逐项处理 required/null、未知字段、枚举/范围、i64 精度、Integer/Float、引用和嵌套路径。不能假定 stdio 的带标签 JSON 可直接当作标准工具参数。
- **验收**：可表示值无损往返；无法表示的契约/值有显式诊断或声明的受支持子集；字段说明足以生成有效请求；业务校验仍只由 core/宿主负责，不在 Adapter 维护第二份规则。

## P7-003：客户端握手、发现和同步调用

- **依赖**：P7-002。
- **交付**：最小连接生命周期、能力发现、调用和结构化失败；接入工作区验证流程。
- **范围**：适配协议外壳与 Command；明确客户端请求 ID 与 ExecutionContext 的映射，不把不同标识混为同一用途。不增加 core 的协议依赖。
- **验收**：真实客户端可发现并调用参考能力；未知工具、输入错误、业务失败和输出违例保持区别；非法外壳不执行业务；断连/EOF 行为明确，诊断不污染协议。当前运行版本与平台有记录。

## P7-004：实际 Agent 纠错与跨入口验证

- **依赖**：P7-003、P3-R03 的真实宿主能力。
- **交付**：可复现客户端使用记录和确定性的协议回归向量；复用 Runtime/Command/stdio 现有 fixtures。
- **验收**：调用者凭发现提交嵌套错误请求 → 读取结构化诊断 → 修正 → 完成真实业务；新增入口不改业务规则。记录实际 Agent/客户端版本；自动化测试不依赖 LLM 每次输出完全相同。
- **阶段增量**：此项完成可报告“同步 Agent 路径完成”，不能报告完整 P7 已完成。

## P7-005：已实现资源、任务与观察映射

- **依赖**：P7-003；资源部分依赖 P4-005，Task 部分依赖 P5-007，观察部分依赖 P6-005。
- **交付**：按 P7-001 支持矩阵逐项接通状态查询、控制和通知；不同子系统可以独立增量交付。
- **验收**：客户端拿到资源/任务引用后可查询、使用或取消；客户端协议取消与 Axiom 协作取消的关系明确；通知丢失后可查权威快照；不支持的操作明确拒绝，不能伪装成功。

## P7-006：有状态 Agent 场景收口

- **依赖**：P7-004、P7-005、P6-006。
- **交付**：实际客户端的对象使用/持续任务场景、安装运行说明、支持矩阵和兼容测试。
- **验收**：发现对象/能力 → 启动工作 → 查询/观察 → 取消或取结果 → 关闭/回收；错误、路径、身份、关联和终态在所有已支持入口一致。客户端中途断开再连接可恢复状态认识；宿主是否继续运行遵循生命周期约定。
- **退出条件**：同步纠错和已声明状态控制均有真实使用记录；不要求做网络部署、账号认证或 core 内 LLM 编排。
