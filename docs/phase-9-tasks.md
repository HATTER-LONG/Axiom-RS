# P9：语义规范与跨实现一致性

## 目标与状态

状态：全部待开发（2026-09-06）。依据 [整体规划](development-plan.md) 与
[设计第 21、22 节](Axiom-design.md)。将已验证行为沉淀为独立于 Rust 类型布局和 stdio
编码的规范，通过第二种真正执行语义的实现验证。该阶段属于长期目标，不阻塞 Rust
首个发布候选；语言和第二仓库未选定，不能现在报告跨语言一致性已完成。

## P9-001：可观察语义规范与能力集

- **依赖**：现有 P3 可观察契约即可开始；P4～P7 每个增量完成后补充对应章节。
- **交付**：`docs/spec/` 下的版本化语义文档，定义动态值、名称/契约、发现、调用、错误、关联；状态章节只纳入已验证规则。
- **范围**：分离规范要求、Rust API 选择与 Adapter 编码；声明基础调用、资源、Task、观察等能力集，给每条规范关联验收向量。
- **验收**：规范中的每项强制语义都有可观察输入/结果；不要求复制 Rc/RefCell、Rust enum 或内部模块；没有把假定的未来行为当成现行标准。

## P9-002：独立一致性向量与 Rust runner

- **依赖**：P9-001 的对应能力集。
- **交付**：仓库中的版本化 `conformance/` 数据和 Rust runner；从现有跨入口 fixtures 提取语义用例，而非复制实现计算预期值。
- **范围**：覆盖严格数值/嵌套/未知字段、注册冲突、快照、错误路径、关联，以及已实现的资源失效/取消竞态/通知缺口。向量格式可表达超出普通 JSON 数字精度的值，不能把 stdio 编码设为所有实现内部模型。
- **验收**：同一向量可驱动不同 runner；规范化只消除已声明的外壳/非确定字段，不抹去有意义差异；预期值独立审查，错误实现样例能被检测。

## P9-003：第二实现范围决策

- **依赖**：P9-002 基础能力集以及明确的原生宿主/第二实现需求。
- **交付**：语言、仓库、负责人、最小能力集、平台及接入场景记录；候选可为 C++，不是既定选择。
- **范围**：区分语言 binding（调用同一个 Rust Runtime）与独立 Runtime 实现；只有后者能验证独立实现一致性。不为证明语言无关而搬运整个项目。
- **验收**：选定实现可独立表达同一组状态/错误，且有真实消费方；未选定时明确待决策，P9-001/002 可继续，后续实现任务不自动启动。

## P9-004：第二实现基础能力集

- **依赖**：P9-003；规范候选与 P8 的兼容范围对齐。
- **交付**：第二仓库的严格值/契约、原子能力注册、同步调用、快照与关联，以及接入同一向量的 runner。
- **范围**：使用所选语言的自然所有权/错误模型，不承诺与 Rust ABI 兼容；先实现基础调用能力集，缺少状态能力必须声明不支持。
- **验收**：两种独立实现通过同一基础向量；未知能力、输入错误、业务失败、输出违例与查询快照行为一致。记录各自版本和差异；Rust wrapper 不算第二实现。

## P9-005：状态能力集与生命周期对照

- **依赖**：P9-004、P4/P5/P6 对应已冻结规范。
- **交付**：逐个实现资源、Task、观察能力集，每个能力集独立报告通过/未支持；对象和线程边界的跨语言设计说明。
- **验收**：相同操作序列产生相同身份失效、状态转移、取消裁决、只读结果和观察恢复语义；语言内部不同步原语不影响对外约定。只有全部声明能力集通过才声称完整范围一致。

## P9-006：兼容演进与规范发布候选

- **依赖**：P9-005。
- **交付**：规范版本规则、两种实现通过矩阵、扩展/不兼容变更流程和候选报告。
- **范围**：把已发现语义分歧分别归为规范遗漏、实现缺陷或明确扩展，并在所属位置修复；不以放宽测试掩盖差异。
- **验收**：旧基础向量在承诺兼容范围内持续通过；未知版本/扩展行为确定；规范、实现和 Adapter 支持声明可对应。发布候选不等于已上传、打 tag 或完成产品采用。
