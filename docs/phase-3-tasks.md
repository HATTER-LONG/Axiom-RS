## 2. MVP 的边界

- 同步 Invocation 接收能力名称、owned Value、ExecutionContext，返回 owned 结果或
  结构化错误；业务内部保持强类型。
- descriptor 与实现原子注册；可执行发现只来自同一注册项。既有元数据注册 API 的
  复用或迁移须明确，不能由两份独立注册表维护同一能力的权威描述。
- Command 仅包含能力发现和调用。Adapter 只有一个，默认 JSON/stdio；若宿主明确
  需要 Agent 客户端，在 P3-003 改选 MCP 并记录理由和对应验收，不同时做两套协议。
- 引入字段说明及宿主确实需要的约束；不做完整 Schema 语言、默认值系统或宏框架。
- 本阶段默认不引入 Resource、Task、Observer、持久化、网络服务、热重载、工作流或 LLM。
  若真实宿主必须有资源或长任务，先明确调整范围及测试，不以错误的简化替代其语义。
- 执行线程模型在宿主确定后冻结；保持重入与锁外执行，跨线程能力不作为无条件前提。

### P3-004：补齐用例必需的参数说明与约束

**目标**：发现结果足以让调用方理解参数并提交有效输入。

**依赖**：P3-001、P3-003。

**范围**：支持字段说明；依据具体参数加入必要单位说明、枚举或范围。每一种约束独立
成增量，记录声明有效性、缺失/null 语义、失败类别和详情；无用例的约束不实现。

**验收**：描述、验证和未来导出读取同一契约；约束边界有正反例，错误保持精确路径；
业务状态规则仍由宿主拥有。新增约束不产生可绕过校验的公开可变表示。

**测试与验证**：契约构造、发现和约束验证的公开测试。

**非目标**：完整 JSON Schema、自动修复、默认值注入或重复业务校验。

### P3-005：冻结调用、失败和执行线程契约

**目标**：确定来自宿主需求的最小调用边界。

**依赖**：P3-003、P3-004。

**范围**：定义窄实现接口和受控业务失败值、调用签名、注册期/调用期关系、线程亲和、
重入、panic 和 context 规则。选一个执行模型，不一次支持多种 executor。

**验收**：

- 输入动态契约由 Runtime 校验一次；转换不重复实现约束，宿主仍检查业务规则；
- 输出合约违例属于内部实现失败，不伪装成输入错误；业务失败保留 message/details；
- 不向外提供任意拼装 Axiom Error 的构造器；新增错误类别随实际失败行为交付；
- 原 context 对宿主可见，child 创建显式，不自动改写关联标识；
- 如选线程亲和模型，明确调用线程和误用防护；如选跨线程模型，才引入所需
  `Send + Sync` 并列出并发测试；不能用 unchecked Send/Sync 迁就宿主。
  类型系统已保证的线程边界可用 compile-fail 测试保护，不额外要求重复运行时检查；
- 不自动捕获 panic，不隐式创建 Task、重试或超时；同步不能包围任意宿主代码。

**测试与验证**：公开实现接口的 compile/use 测试、线程边界测试。

**非目标**：调度器、线程池、通用依赖注入和多执行模型框架。

### P3-006：原子注册与权威发现

**目标**：描述和实现作为同一可执行项生效。

**依赖**：P3-005。

**范围**：Runtime 所有权和注册；复用 capability 的名称、描述和冲突规则。明确既有
metadata registry 与可执行存储的关系，必要 API 调整提供迁移示例。

**验收**：重复注册保留原描述与原实现，失败无半注册；发现保持大小写敏感、排序确定、
owned snapshot、未知为 None、不执行宿主代码。调用与发现没有独立漂移的描述副本。

**测试与验证**：注册冲突、快照和公开组合测试；更新架构规则。

**非目标**：替换、移除、热加载、批量事务；无并发注册需求不加入锁。

### P3-007：同步调用与结构化失败

**目标**：交付输入校验、宿主执行、输出校验的完整路径。

**依赖**：P3-006。

**范围**：解析、捕获状态、离开基础设施同步、验证和执行；未知能力、输入错误、业务
失败、输出违例的分类及必要结构化详情。输出失败保留底层诊断路径与预期/实际信息。

**验收**：非法输入不执行业务；嵌套输入错误原样可读；发现 None 与调用未知能力明确
区分；业务失败保真，输出违例不会返回伪成功。用代码边界和行为测试保护单一校验来源，
不为测试公开私有调用计数。

**测试与验证**：公开 API 成功/失败表驱动测试。

**非目标**：Command 外壳、观察器、取消、自动转换或参数默认值。

### P3-008：重入、线程模型和关联传播

**目标**：验证 P3-005 承诺的执行行为。

**依赖**：P3-007。

**范围**：回调重入调用/发现；root/child 和失败路径的 context；如支持跨线程，验证
阻塞能力不阻止发现或独立调用。如使用线程亲和模型，验证业务在约定线程执行及误用防护，
不宣称支持跨线程并发。

**验收**：基础设施锁或运行时可变借用不跨越宿主回调；关联值保持不变；重入无死锁。
并发测试使用 channel/barrier 和有界失败等待，不依赖 sleep 猜测顺序。

**测试与验证**：重入、线程模型和关联传播集成测试；有具体内存安全风险时，按 README
选择专项工具并记录适用范围。

**非目标**：承诺所有能力可并发、提供 executor、资源生命周期或 Task。

### P3-009：最小 Command 边界

**目标**：本地动态调用和外部入口共享发现/调用路由。

**依赖**：P3-008。

**范围**：协议无关的列举/查询能力与调用命令、响应和请求版本规则；严格验证请求
外壳。明确未知命令、缺失/多余字段、非法名称/关联标识的类别、路径和详情。

**验收**：结构错误不进入宿主；业务输入仍只由 Runtime 契约校验；发现与原生查询一致。
外壳路径和能力参数路径的关系有明确约定，可无损定位；不通过重建错误丢失诊断信息。

**测试与验证**：请求结构和原生/Command 一致性测试。

**非目标**：统一 Resource/Task 命令全集、传输编码或第二份业务校验。

### P3-010：接入宿主并测量维护成本

**状态**：参考宿主已接入四个能力；契约与转换漂移由
`omitted_size_w_changes_observable_volume` 保护；维护量见

**目标**：3～5 个真实能力共用同一套 Axiom 接入。

**依赖**：P3-007、P3-009；可在 P3-007 后先开始原生接入。

**范围**：宿主保留强类型业务，适配 Value 输入输出，登记 descriptor；记录各能力
业务代码、契约声明和转换代码的边界及维护量，包含一次新增/修改参数的验证用例。

**验收**：契约变化与转换逻辑不一致能由测试暴露；新增调用入口无需更改业务规则。

**非目标**：将宿主领域模型迁入 core，或自动生成整个 SDK。

### P3-011：实现一个外部 Adapter

**状态**：JSON/stdio Adapter 已实现。帧限制在读取阶段生效；`$i`/`$f`/`$o`
无歧义对象表示；协议错误走同一套 `encode_value`。深度按 Axiom `Value` 层级计。

**目标**：独立调用方通过 P3-003 选定入口发现并执行宿主能力。

**依赖**：P3-009、P3-010。

**范围**：隔离编码/传输依赖；默认 JSON/stdio，包含解码、Command 转换、描述与响应
编码。定义帧边界、协议版本、EOF、畸形请求、输出通道和诊断通道；若选 MCP，改用
该协议版本的交互，并保留下述核心表示验收，不另造一套 stdio 协议。

**验收**：

- 往返不丢失 i64 精度，Integer/Float 不因 JSON 重编码静默混同；非有限数、越界、
  重复键和不支持的表示明确拒绝，必要时使用明确标记或声明受支持子集；
- 输入帧大小和嵌套深度有明确边界，在递归转换前拒绝超限输入；
- ErrorKind、结构化 Path、details、关联信息可被外部程序读取；名称、契约、输出
  类型与协议要求不兼容时显式报告，不能静默修改核心语义；
- discovery 导出契约不维护第二套规则，Adapter 不重复校验业务参数；
- 协议输出不混入诊断日志，退出和错误响应行为有测试；核心无协议依赖。

**测试与验证**：数值/嵌套/错误往返测试、进程级请求响应测试；将 Adapter 包的格式、
Clippy、文档、测试及适用覆盖率检查接入 README 定义的工作流。

**非目标**：多 Adapter、网络部署、认证协议或 LLM 调用。

### P3-012：跨入口一致性与 MVP 收口

**状态**：参考宿主的 Runtime/Command/stdio 同一 fixtures 比较、进程级发现→错误
→修正闭环已作为测试落地。真实宿主使用验证未完成，不以参考案例替代。

**目标**：证明同一业务能力只接入一次即可供本地和外部使用。

**依赖**：P3-008 至 P3-011。

**范围**：相同 fixtures 经过原生 Runtime、Command 和所选 Adapter，规范化响应外壳后
比较结果/错误；维护可执行演示、真实宿主验收记录、README 和迁移说明。

**验收**：

1. 外部调用方仅凭发现信息完成有效调用；
2. 错误嵌套参数 → 精确诊断 → 修正 → 成功，具有自动化端到端测试；
3. 各入口业务结果、错误类别/路径/详情和宿主所见关联一致；
4. 输入错误未执行业务，发现无副作用，业务失败与输出违例明确不同；
5. 参数变更测试和接入维护成本有记录；已有真实宿主使用验证，不以参考案例替代；
6. 所有代码、文档和检查覆盖新增包；P3-001/P3-002 回归仍受保护；
7. 依据宿主反馈选择下一阶段的资源或 Task 闭环，或记录暂不需要状态扩展。

**测试与验证**：端到端、文档示例和检查脚本回归受保护，按 README 验证最终代码候选。
报告实际结果和仍未完成的验收，不用覆盖率替代使用验证。

**非目标**：为了收口提前做全部状态系统、第二个 Adapter 或承诺稳定 ABI。

## 5. 完成定义

修复基础漏洞，真实宿主完成一次接入，调用方可发现、执行并据错误纠正请求；本地与
一个外部入口共享契约、业务实现和诊断语义，适用质量门实际通过。Resource、Task、
观察和更多 Adapter 由使用证据驱动后续增量，不作为本阶段的默认前置基础设施。
