# P5：宿主驱动的持续任务

## 目标与状态

状态：全部待开发（2026-09-06）。见 [整体规划](development-plan.md) 与
[设计第 6、13、15～17 节](Axiom-design.md)。Invocation 负责发起，Task 保存持续工作的
身份、状态和结果；Axiom 不新增通用 executor、线程池、工作流或持久化系统。
P5 基础任务不依赖 P4；只有 P5-007 的资源组合依赖 P4。
验证流程统一遵循 README，状态竞态使用确定的推进顺序和有界等待。

## P5-001：冻结任务状态机和宿主推进方式

- **依赖**：P3-R01 的长工作场景；同步核心已实现。
- **交付**：`docs/task-contract.md`：状态转移表、谁可执行每条转移、取消确认、结果保留/回收、关闭流程和创建关联。
- **范围**：以 Pending/Running/Succeeded/Failed/Cancelled 为候选；取消请求与 Cancelled 终态分开。选择宿主事件循环推进或宿主 worker + 消息回传中的一种真实需要的机制。
- **验收**：列明开始前取消、执行中取消、完成与取消竞争、重复取消、启动失败、晚到回报、宿主退出的结果；终态不能互相覆盖。文档说明为什么当前同步 stdio 的阻塞调用不能承担可取消长工作。

## P5-002：任务身份、权威状态与只读结果

- **依赖**：P5-001。
- **交付**：task 模块、Task 标识/引用、任务快照、状态转移与结果/错误读取；必要契约/错误类型和架构规则。
- **范围**：结果采用 owned 动态数据或 P4 明确的引用；记录创建 context，不把 context 变成任务服务容器。查询不推进任务。
- **验收**：非法转移不改变状态；终态结果稳定；重复结果读取不重新执行、不消耗结果；未完成、成功、失败、取消、未知身份的读取有确定区别。快照与后续变化隔离。

## P5-003：启动接口与宿主工作桥接

- **依赖**：P5-002。
- **交付**：一个启动 capability、受控状态报告接口及一个符合 P5-001 的宿主推进实现。
- **范围**：Invocation 返回 Task 引用后结束；工作继续由宿主管理。状态写入只走 task 权威边界；worker 不携带线程亲和 Runtime，只有确需跨线程的数据/报告句柄具有相应 bounds。
- **验收**：启动失败不留下不可终结的任务；返回引用可查询；实际工作只启动一次；运行中仍可处理发现/状态命令；宿主回调之外不保留目录可变借用。记录工作 panic/失联由谁报告失败或关闭，不能永久伪装 Running。

## P5-004：进度与关联传播

- **依赖**：P5-003。
- **交付**：最小进度快照和宿主更新入口；创建 Invocation → Task → 显式子操作的关联测试。
- **范围**：按宿主选择已完成量/总量或阶段描述，不强制所有任务有百分比；冻结可否回退、未知总量和终态更新规则。
- **验收**：非法进度明确拒绝；终态后的晚到更新不改写结果；无进度仍可正确查询状态；创建 correlation/parent 在成功、失败、取消和结果读取中保持约定含义。

## P5-005：协作取消与竞态裁决

- **依赖**：P5-003。
- **交付**：取消请求入口、宿主观察/确认接口及状态机裁决实现。
- **范围**：取消是请求，不承诺强制终止；不把客户端断开等同于取消，不通过杀线程实现取消。使用 P5-001 明确的终态胜出规则。
- **验收**：覆盖开始前、运行中、完成前后、重复和拒绝取消；完成与确认取消两种先后顺序均只有一个终态；终态结果不被晚到写入覆盖；宿主不支持即时取消时响应真实表达请求状态。

## P5-006：留存、回收与宿主退出

- **依赖**：P5-004、P5-005。
- **交付**：显式任务回收/容量策略和关闭接口；不默认加入数据库或时钟驱动清理服务。
- **范围**：定义活跃任务能否删除、终态保留策略、容量满时行为、报告句柄失效和宿主退出时工作处理。析构不能无限等待不可取消工作。
- **验收**：重复回收结果确定；旧 ID 不命中新任务；回收后查询明确失效；持有旧报告端不复活任务；关闭时无无限阻塞、资源泄漏或错误线程析构。若不能等待某类工作，报告具体宿主责任。

## P5-007：任务命令、实际工作与资源组合验收

- **依赖**：P5-006；仅资源组合部分依赖 P4-005 的资源实现与命令，实际对象沿用 P4-001 的宿主场景。
- **交付**：task list/get/cancel/result/forget（最终命名随协议冻结）的 Command/stdio 路由，以及一个真实长工作的进程级场景。普通同步 invoke 保持原语义。
- **验收**：启动后下一条请求可查进度/取消；本地与外部终态、结果、错误、关联一致；重复读结果不重算。若工作使用资源，覆盖运行中关闭资源、取消释放使用权、任务结果引用失效；没有资源依赖的场景明确记录不适用。
- **退出条件**：真实持续工作可以从外部发现、启动、查询、取消、取结果和回收；不能只用手动改状态的测试替代工作桥接验证。资源组合可后补，但 M2 必须完成实际需要的组合。
